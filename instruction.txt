BACKEND VIDEO/AUDIO DOWNLOAD - ROMAN URDU GUIDE

Maqsad
------
Yeh FastAPI backend app ko video ki available resolutions aur audio-only download links deta hai. Video download backend par MP4 mein merge hota hai, is liye video aur audio alag streams hon to app ko FFmpeg merge karne ki zaroorat nahin.
Sirf aisa content download karein jiske liye aap ke paas haq ya ijazat ho. Kisi platform ki terms aur local qawaneen ka khayal rakhein.

1. Zaroori software
-------------------
- Python 3.10 ya naya
- FFmpeg (PATH mein ffmpeg command accessible ho) - alag video/audio streams ko MP4 banane ke liye lazmi
- Git (optional)

2. Windows par backend chalana
------------------------------
PowerShell mein backend folder kholen:

    cd D:\fro\backend
    py -m venv .venv
    .\.venv\Scripts\python -m pip install -r requirements.txt
    .\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

FFmpeg pehle se install ho aur PATH mein ho. Install karne ke baad naya PowerShell kholen.
Agar YouTube "content is not available on this app" error aaye to backend band karke
requirements dobara install karein, phir backend restart karein:

    .\.venv\Scripts\python -m pip install -r requirements.txt

Local PC par status: http://127.0.0.1:8000/
PC video test app: http://127.0.0.1:8000/
API documentation: http://127.0.0.1:8000/docs

Browser test app mein URL aur optional quality dain, "Check formats" dabayein,
phir format ke samne Download button dabayein. Download browser ke Downloads
folder mein nazar aayega. Download file backend se aati hai.

3. App se API call
------------------
Extract aur available download links:

    GET http://<BACKEND-IP>:8000/api/download?url=<ENCODED_VIDEO_URL>

Quality mangne ka misaal:

    GET http://<BACKEND-IP>:8000/api/download?url=<ENCODED_VIDEO_URL>&quality=720p

URL parameter ko app mein URL-encode karein. Android emulator ke liye base URL:

    http://10.0.2.2:8000/

Physical Android phone par base URL PC ka local Wi-Fi IPv4 address ho, misal:

    http://192.168.1.25:8000/

Phone aur PC aik hi Wi-Fi par hon aur Windows Firewall TCP port 8000 allow kare.

4. JSON response
----------------
Response mein title, thumbnail, duration_sec, selected_quality, selected_ext, download_url, audio_url aur formats hotay hain.

- download_url: MP4 file ko backend se download karne ka link. Android DownloadManager ko yahi link dein.
- audio_url: audio-only file download karne ka link. Iska extension source format ke mutabiq m4a ya webm ho sakta hai; har audio stream MP3 nahin hoti.
- formats: available video qualities ke saath audio-only formats bhi.
- format item ka type video+audio, video-only, ya audio-only ho sakta hai.

Download karne ke links kuch waqt baad expire ho sakte hain; zaroorat par /api/download dobara call karein.
Video quality ka link MP4 return karta hai. Is ke liye FFmpeg server par chahiye.

5. Android integration
----------------------
AndroidManifest.xml mein yeh permission add karein:

    <uses-permission android:name="android.permission.INTERNET" />

Retrofit/Gson dependencies:

    implementation "com.squareup.retrofit2:retrofit:2.11.0"
    implementation "com.squareup.retrofit2:converter-gson:2.11.0"

API interface ko GET api/download ke saath url aur optional quality query bhejni chahiye.
Response mein download_url aaye to usay DownloadManager se download karein. Audio ke liye audio_url use karein.
Production mein base URL ko HTTPS par deployed backend domain se badlein; cleartext HTTP ko production mein on na karein.

6. Configuration aur deployment
-------------------------------
CORS_ORIGINS environment variable mein web app ke origins comma-separated dein. Misal:

    $env:CORS_ORIGINS="https://app.example.com"

Android native app ke liye CORS aam tor par zaroori nahin.
Production mein HTTPS reverse proxy, request rate limit, monitoring aur hosting resource limits set karein.
Backend ko internet par khulasa karne se pehle authentication/rate limiting lagayein. Random public URL par service na chalayein.

7. Error check
--------------
- 400: URL ghalat, local/private IP, ya supported scheme nahin.
- 422: provider ne media info/download reject kiya, ya FFmpeg/format masla.
- Railway par "ffmpeg is not installed" aaye to root Dockerfile wali latest revision deploy karein. Railway image rebuild/redeploy ke baad video download dobara test karein.
- /docs par endpoint request aur JSON response check karein.
- App mein HTTP error body aur network exception log karein; real production credentials/logs share na karein.
